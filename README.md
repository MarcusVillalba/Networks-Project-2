### Run Instructions
  Download all the files in the repository (server.py, client.py, and the assets/colors folder). To run this project yourself, you will need pygame. Install with "pip install pygame". I used pygame version 2.6.1 myself. Make sure your computer is connected to wifi. On line 7 of client.py, you'll see "SERVER_IP = "192.168.1.177". This is a hardcoded IPv4 address. Run "ipconfig" in your terminal, find where it reads "IPv4 . . ...", then replace the address on line 7 with your own. When the files run, the clients will be receiving data from this address. Once pygame is installed and you have replaced the IP address in client.py with your own, the program should be ready to run. Run server.py first, then in up to four separate terminals, run client.py. Each will open up their own pygame window. Each client can swap their colors and ready up using the left and right arrow keys and the spacebar respectively. Once all players are ready, a countdown will begin. This countdown doesn't affect the experience, but if this were part of a real game, the game would then be loaded at the end of the countdown. Conclude by clicking the "x" in the top-right of each of the clients' pygame windows, then use CTRL+C in the server terminal to terminate the server.

### System Description
##### Goals
  This project is a mock pregame lobby. In many online multiplayer videogames, teammates or competitors start their experience by joining a lobby. Consider, for instance, Fortnite. When players wish to queue into a game together, they join a lobby together where they can change their character models, modify their settings, etc. Then, when a player is ready to start the main gameplay, they "ready-up", and when all players of the lobby are ready, they are loaded into the game as a group. This project is a very small scale version of that. Players join the lobby of an arbitrary game. Their character model is just a single-colored dot, and in the lobby, they have the choice to change the color of their dot and ready up. The server keeps track of which players are ready, and if all players are ready, a countdown to the main gameplay begins. Were this a real product, the players would then be loaded into a game. The server handles many things. For instance, since each player is represented with a dot, it can be easy to lose track of who is who, so the server ensures that only one player can have a color at a time. Additionally, if a player closes the lobby window, the server will detect this and modify every remaining players' lobbies so that only the remaining players' dots are displayed. If a player disconnects during the countdown, the server will detect this, cancel the countdown, and remove this player's dot.

##### Main Modules
  There are three components: server.py, client.py, and the assets/colors folder. server.py is the server. It broadcasts to any computer on the same wifi connection and uses UDP to communicate with the clients. client.py is the client, where the frontend features are accessed by the users. It opens a pygame window where users can change the color of their dot and ready up. assets/colors is just where the different dot images are stored. When users change their color, the server sends different files from the colors folder to load into the pygame window.
